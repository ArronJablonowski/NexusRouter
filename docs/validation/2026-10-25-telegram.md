dispatcher**, plus a simulated local model provider. It deliberately loses the
first admission acknowledgement, closes and reopens connector state, and
continues observation with the original submission key. Exactly two model calls

synthetic marker, assistant answer and new prompt. Neither call receives host
tools. Telegram transport is separately exercised against a loopback HTTP server.
No Telegram API was contacted with a bot credential.

claiming the connector state directory. The new unowned-database protection
correctly rejected it. The test was corrected to follow production's order:
claim private state first, then start the dispatcher. Its final race run passes.

## Broader regression limitations, reproduced on the starting revision

A broader affected-boundary run was attempted, rather than reporting only the
new tests. Three existing tests failed. Each failure was reproduced separately
against an untouched archive of the starting revision above, without Telegram:

1. `TestDispatcherHealthRenewalDuringBlockedProvider`: provider not entered.
   Its existing recovery fixture uses synthetic resource data and does not reach
   the intended blocked-provider boundary under current admission requirements.
   The identical failure occurs in the baseline (5.546s package run).
2. `TestDaemonRestartRecoversInterruptedModelWithoutRedispatch`: subprocess audit
   initialization fails before readiness. The helper supplies only PATH, token
   and process-owner variables, omitting HOME; the executable requires a home
   directory to initialize its mandatory subprocess audit. The baseline fails
   identically before this test can exercise recovery.

   larger than its older 64 KiB fixture bound (`browser response unreadable`, no

   shell. Telegram changes no embedded assets or shell responses.
