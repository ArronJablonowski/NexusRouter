# Chat approvals, automatic approval and creative quality ratings — 2026-10-14

Pending calls have an inline **Approve once** button. An already consumed approval is shown as **Approval used**, explaining that it was approved for this call and cannot authorize another one. This is a presentation correction, not renewed authority. Existing pending-call argument/digest validation, authenticated decisions, leases, cancellation/expiry and uncertain-outcome fences remain intact.

Settings adds **Auto-approve all tool calls**, default off, saved as `tools.auto_approve`. As with other runtime settings, Save preserves the choice and an owning-service restart activates it. It applies to permitted calls in the serving chat host; it does not enable disabled tools, grant new filesystem/network/cloud access, override denied policy or expand delegated/remote capabilities. The trusted presenter records a bound durable decision as `auto_approval_setting`, after verifying the exact pending record through existing approval-control storage. The original gate still consumes approval under its normal lease and never replays spent/uncertain work. Chat identifies automatically approved decisions. Saving from older clients that omit the field preserves its value. Auto-approval remains off in the deployed operator configuration.

The Web UI no longer asks the operator for money or a binary accepted/rejected verdict. It asks for a whole-number quality rating from 1 to 10. The server derives an available task-level USD model-cost estimate from the existing routed/auxiliary accounting totals; incomplete coverage/pricing remains explicitly unavailable. This is an estimate, not a bill, and excludes electricity/unmetered external tools. The original numeric cost column has a zero placeholder only when `cost_status` explicitly says unknown; that placeholder is never used as a measured zero in routing. Existing legacy API/CLI feedback remains readable and supported.

Ratings retain the producing model/provider from completed durable turns and a creative category inferred from the current user request. Current categories cover image requests, poetry, fiction, marketing, design and documents; unclassified general prompts do not inherit creative preferences. Revisions replace the current opinion rather than adding duplicate preference samples. Automatic LLM selection receives bounded, decaying subjective-quality opinions for matching categories, normalized across the full 1–10 range. Objective execution facts/reliability/cost are not fabricated from scores. Explicit model choices, admission/permission/cost limits and objective evidence rules remain authoritative. Ratings of image workflows concern the orchestrating LLM/pipeline; this does not select a different ComfyUI diffusion checkpoint. The heuristic categories, physical mobile/screen-reader qualification and calibrated provider billing remain limits.
