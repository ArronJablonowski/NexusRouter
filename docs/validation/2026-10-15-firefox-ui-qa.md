# Firefox and responsive Web UI QA — 2026-10-15

## Reproduced defects and fixes

1. **Field boundaries lost contrast in the shared styling update.** The shared field border `#345e69` measured about 2.46:1 against the panel and 2.63:1 against the field background, below the 3:1 non-text contrast target. Changed text fields/selects to `#578390`. Updated the static checks to current colors and added computed browser checks for visible enabled field boundaries; disabled controls and borderless composer text are handled separately.
2. **Firefox could retain the previous stylesheet during live updates.** Detecting a new ETag and cloning a link with the same URL did not reliably apply the new CSS in Firefox. The replacement link now uses a same-origin filename containing the stylesheet SHA256, served as an exact alias of the current embedded CSS. Strong quoted SHA256 ETags are required. Authentication and the strict asset query policy remain unchanged. CSP and authorization are unchanged. Firefox reproduced the failure before the fix. The regression test first fails the new CSS download, checks that the old sheet/draft remain, then restores delivery and verifies the updated CSS, draft, focus and original document survive without reload.

3. **Populated ComfyUI saved-job buttons overflowed narrow Firefox windows.** Installed checks measured a 434px page inside a 390px viewport. Long job-reference buttons exceeded their container; the original short fixture key did not cover this. Scoped ComfyUI wrapping/grid constraints now retain the entire reference and wrap uncertainty notices. Both browsers pass a 128-character-reference regression at 320/390/844px, including the existing no-resubmission fences.

## Repeatable browser coverage

Added an isolated Firefox WebDriver BiDi harness with no external automation dependency. It reuses 24 existing same-origin API fixture scenarios and assertions: all pages; uploads and rejection recovery; exact download bytes and inline images; sticky header/composer; ComfyUI uncertainty fences; late approvals; chat rename/pin; explicit cloud registration; dirty settings; live styles/stats; chat/workboard failure recovery; Spark history and CSRF; routing; jobs; inspector; Cron; collaboration; dependencies; logging; remote models/odometers; discovery and advertisement.

All 15 pages are checked at 1440, 1024, 768, 390 and 320 CSS pixels. Chat viewport checks additionally include 320×568, 390×480 and 844×390, with long messages, scrolling, retained drafts and routing details. Checks cover page overflow, hidden-state preservation, accessible button names, minimum control dimensions, keyboard focus, reduced motion, enabled opaque button text contrast and field boundaries. Private Firefox narrow-page screenshots were inspected.

Firefox 157.0.1 and Chrome 155.0.8059.85 were used. On this macOS host direct Firefox execution could not load the profile; the harness launches a new instance through LaunchServices with an owned temporary profile and loopback-only debugging. Only test-profile focus/tab-navigation/reduced-motion preferences are set; the user's browser/profile/security configuration is untouched. A real content pointer action establishes page focus before Tab probes, preventing Firefox's URL bar from invalidating later focus probes. Unsupported automation operations fail rather than silently skipping assertions. Firefox download handling verifies actual bytes, and file uploads use BiDi file selection.
