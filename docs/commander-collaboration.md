# Automatic commander collaboration

A configured top-level commander can discover eligible paired commanders using `list_commanders`, then send self-contained assignments with `delegate` or `delegate_batch` and `instance_id`. Local and remote assignments share the existing delegation call budget. The parent synthesizes returned, explicitly untrusted results. Task context must be supplied in the assignment; this does not share a filesystem or a project database.

The host needs configured outbound credentials, the remote trust file and the recorded-dispatch directory. Both serving entry points install the bridge when those are present. Each peer must allow info, dispatch, inspection and cancellation, permit the destination's declared commander model and requested context, and have protocol capability version 2. Private tasks require private permission and local inference. Cloud inference requires explicit peer permission and a non-private parent. Discovery is advisory; receiver admission remains authoritative.

Consultations use a single remote hop, no nested tools or further remote collaboration, and the existing 30-second delegation deadline. They require a declared zero estimated model cost; paid model collaboration is not admitted until aggregate cost reservation is implemented. Existing worker/project-host capabilities are not expanded. This is bounded commander consultation, not unrestricted mesh messaging, project replication, or multi-hop orchestration.

The parent worker journal records the assignment lifecycle. Recorded dispatch binds the work ID to the peer, caller identity and exact task hash before sending. The same ID identifies the remote submission for inspection. There is no automatic retry or rerouting after uncertain delivery. Cancellation is attempted through the paired peer; the destination enforces the deadline independently. Old hosts are unavailable for consultation rather than silently falling back to a different execution mode.
